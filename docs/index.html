Flashes the OpenMANET-XIAO-Gateway firmware onto a Seeed XIAO ESP32-S3 + Seeed XIAO WM6108 (HaLow) node. Works in Chrome or Edge over USB — no software to install.

This flashes firmware with placeholder configuration (open HaLow uplink, default local Wi-Fi credentials). See "After flashing" below to set your real values — nothing here bakes in your Wi-Fi/HaLow credentials, they're entered later over the device's own local network, not typed into this page.

Before flashing

  1. Plug the XIAO ESP32-S3 in via USB-C.
  2. Click "Connect & Flash" above and pick the device's serial port when your browser asks.

After flashing

  1. The device boots and starts its own Wi-Fi access point (default SSID xiao-gateway, password openmanet — see the firmware's defaults if these have changed).
  2. Connect your laptop or phone to that Wi-Fi network.
  3. Browse to http://172.16.50.1/ — the on-device config page.
  4. Use the config page's Scan for HaLow APs button to find the mesh Pi's access point, then click the result to fill in its SSID.
  5. Set the uplink security/passphrase (open/OWE/SAE only — see the Pi-side reference for what the mesh Pi expects) and your own local Wi-Fi SSID/password, then Save and Reboot.

Reading the on-board LED

The XIAO's user LED reports how far the node got, with no cable and no phone attached. Full bring-up procedure is in the hardware and bring-up guide.

  • Fast triple-blink — the HaLow radio didn't initialize. Check the module is seated and that you flashed a build matching your hardware.
  • Slow blink — radio up, looking for the Pi's access point.
  • Double-blink — associated, but the Pi hasn't given it an address yet.
  • Solid — uplink up.

Locked out of the config page? Hold the BOOT button for 5 seconds while the node is running to restore the default settings — the LED starts blinking fast after about 1.5 seconds to confirm, and releasing before 5 seconds cancels.

Regulatory / country code

This firmware is US-only (902–928 MHz), because the hardware is. The XIAO HaLow board carries a Quectel FGH100M-H, a 902–928 MHz part, and the board calibration file the firmware loads is Morse Micro's bcf_fgh100mhaamd.bin — listed upstream as "FGH100M-H (US)". Seeed likewise document the board as North America only. There is no EU/UK/JP variant of this module to build for.

The channel list is baked in at compile time (CONFIG_HALOW_COUNTRY_CODE="US") and can't be changed afterward from this page or the on-device config UI. Your mesh Pi's HaLow radio has to be on the same regulatory domain — a mismatch is silent, and shows up as a scan that finds nothing rather than as an error.
