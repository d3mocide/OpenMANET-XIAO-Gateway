Node

Relay exists for when the Pi itself can't run a HaLow access point (see design/PI_SIDE.md item 0) — a relay joins the Pi's ordinary local Wi-Fi directly and offers its own HaLow radio as an AP for other XIAOs to associate to, instead of associating to a Pi over HaLow itself. Changing this changes which radios come up entirely, not just a config value — it needs a reboot to take effect either way.

HaLow uplink

Must match the mesh Pi's (or relay's) HaLow access point.

Scanning only covers channels legal in this firmware's region, and briefly interrupts an established uplink. Click a result to fill in its SSID.

Used only when security is SAE. HaLow has no WPA2-PSK mode.

Only needed when the AP above is a relay node rather than a real Pi — a relay's HaLow AP runs no DHCP server (see design/ROADMAP.md item 8), so every leaf that joins it needs its own fixed address in that subnet. Leave unchecked when joining a real Pi.

Local Wi-Fi

The 2.4GHz network phones, tablets and ATAK devices join.

8–63 characters. Leave blank to keep the current passphrase — switching to an open network can only be done from the serial console (gwcfg-set-softap <ssid> -).

Wi-Fi uplink (to the Pi)

The Pi's own local Wi-Fi network — the same one a phone joining the Pi directly would use. Ordinary WPA2-PSK, not HaLow security.

HaLow AP (to other XIAOs)

What other XIAOs' HaLow uplinks associate to. Marked ALPHA in Morse Micro's own SDK and untested by this project on real hardware — see design/ROADMAP.md item 8 before relying on it in the field.

OWE is not supported for HaLow AP mode.

No auto-selection is possible here (see design/ROADMAP.md item 8) — get the legal (op-class, channel) pairs for this build's region from the serial console: gwcfg-list-halow-channels.

No DHCP server runs here — every leaf XIAO needs a static IP of its own in this subnet, set on its HaLow uplink's "Static IP" field above.
